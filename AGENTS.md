## Build / flash / monitor

```powershell
pio run                          # build (env: nucleo_f303re)
pio run -t upload                # flash via on-board ST-Link
pio run -t clean
pio device monitor               # serial console: monitor_speed/monitor_port are in platformio.ini
```

- **Serial console: USART2 → ST-Link virtual COM port, 230400 bps, 8N1, currently `COM5` on the Windows 11 host** (user-reported 2026-10-26; the COM number can change if the board is re-plugged — check Device Manager or `pio device list`). Older docs said 115200; confirm against the USART2 init (`MX_USART2_UART_Init` / `stm32-foc.ioc`) if output looks garbled.
- `platformio.ini` sets `monitor_speed = 230400` and `monitor_port = COM5` (added 2026-10-26). If the board enumerates on another port, override with `pio device monitor -p COMx` or update `monitor_port`.

- `pio` is at `C:/Users/akrap/.platformio/penv/Scripts/platformio.exe`.
- No unit tests, no linter, no CI. Verification = successful `pio run`, plus the optional host simulations in `tools/sim/` (need a host gcc; see `tools/sim/README.md`).
- Debug: VS Code "PIO Debug" (`.vscode/launch.json`), or cortex-debug MCP at `http://localhost:7580/sse` (`.mcp.json`).

## Hardware-critical build flags — do not remove

- `hardfloat.py` (pre-script) force-adds `-mfloat-abi=hard -mfpu=fpv4-sp-d16`. Without it all float DSP runs soft-float and the ISR will miss deadlines. The library's fast paths also rely on it (`VSQRT`, `VFMA` via `__FP_FAST_FMAF`).
- `-Wl,-u,_printf_float` in `platformio.ini` is required for `%f` in `printf`. Removing it silently breaks float printing.
- `-D__PLATFORMIO__` selects the `_write()` retarget in `Src/freertos.c` (prints over USART2, 230400 bps). The non-PIO branch is dead code here.
- `platformio.ini`: `build_flags` set `-O2`, `-DFW_VERSION=1` and the FreeRTOS include paths; `build_unflags = -Os` removes PlatformIO's release default so `-O2` is the only optimisation level (applies to `Lib/foc-lib` too). The `[platformio]` section sets `include_dir = Inc`, `src_dir = Src`. `-DCFG_TUSB_MCU=OPT_MCU_STM32F3` is a TinyUSB leftover from the upstream project (unused here, harmless).
- `-DFOC_LIB_USE_CONF` makes `foc_lib.h` include the port header `Inc/foc_lib_conf.h`, which defines `FOC_FAST_CODE` to place the ISR call tree in CCM SRAM (~27 % faster than flash). It relies on the `.ccmram` copy loop in `main()` (USER CODE 1). Tag any new function called from `FOC_Update` with `FOC_FAST_CODE`, or every call to it goes through a long-branch veneer into flash.
- **foc-lib stays platform-neutral**: no MCU, HAL or linker specifics in `Lib/foc-lib`. Any platform's PWM ISR feeds `adc_v_*`, calls `FOC_Update()` and applies `pwm_a/b/c` and `outputs_enabled`. Platform tuning goes in the port's `foc_lib_conf.h`. Without the flag, `FOC_FAST_CODE` expands to nothing (the host sims build this way).
- **Never add `-ffast-math`**: it lets the compiler delete the NaN/inf guards (`Normalize_Angle`, eSMO reset guard). Use `-O2` (or `-O3`) for `foc_lib.c`; `-Os` makes Park/eSMO markedly slower.

## CubeMX-generated code — the #1 footgun

Most of `Src/` and `Inc/` is regenerated by STM32CubeMX (source of truth: `stm32-foc.ioc`; regeneration config: `stm32pio.ini`). **Edits outside `/* USER CODE BEGIN ... */` / `/* USER CODE END ... */` blocks are silently deleted on regeneration.** Put all hand-written code in those blocks; heavier logic belongs in `Lib/foc-lib/foc_lib.c`.

- Pin/peripheral map: `stm32-foc.txt` (readable export) or `stm32-foc.pdf`.
- `TIMER_config()` in `Src/freertos.c` overwrites the CubeMX TIM1 PSC/ARR at runtime from `PWM_FREQ` (center-aligned). Do not "fix" the CubeMX period expecting it to take effect. **The PWM/ISR rate is whatever `PWM_FREQ` in `Lib/foc-lib/foc_lib.h` says (10 kHz as of 2026-10), not any figure quoted in docs.**

## Control architecture

- **FOC runs in the ADC ISR**, not a task: `ADC1_2_IRQHandler` → `ADC_IRQ_Fast_Dispatch()` (bypasses `HAL_ADC_IRQHandler` for ADC1 JEOS; other ADC interrupts still go through HAL) → `HAL_ADCEx_InjectedConvCpltCallback` (`Src/freertos.c`) → `FOC_Update()` → writes TIM1 CCR1-3. Triggered by TIM1 CC4 once per PWM period. Keep ISR code allocation-free, `printf`-free and fast. PC8 is driven high for the callback's duration (ISR timing on a scope).
- **`FOC_Update()`** (in `foc_lib.c`): ADC → currents (with LPF), then by mode:
  - `FOC_CALIBRATION`: Rs / Ld / Lq injection at `theta = 0`.
  - `FOC_TORQUE_CONTROL` / `FOC_SPEED_CONTROL`: startup state machine `MOTOR_IDLE → MOTOR_STARTUP_ALIGN → MOTOR_STARTUP_RAMP (I-f) → MOTOR_STARTUP_TRANSITION → MOTOR_RUNNING`, all current-controlled; `MOTOR_RUNNING` uses the observer angle (torque mode applies `FOC_MTPA(is_ref)` first).
  - **Direction**: set with `FOC_Set_Direction()` (refused while `outputs_enabled`; to reverse, stop first: the drive cannot brake). `speed_ref` and `is_ref` are relative to `rotor_dir` (positive = in that direction); a negative `speed_ref` means 0. Do not write `rotor_dir` directly.
  - Then inverse Park at `foc->theta` (+ `IPARK_DELAY_COMP` advance) and SVPWM — **only if `foc->outputs_enabled`**; otherwise duties stay 0.
- **`foc->outputs_enabled` is a HAL contract**: when false (idle, coast, faults) the HAL must disable the PWM outputs / gate driver (e.g. TIM1 MOE). A 0 duty alone keeps the low-side switches on in complementary mode.
- **Angles**: the transforms use `foc->theta` / `foc->omega`, set by the state machine (align angle, forced I-f angle, blended angle, observer angle). Never write `smo.theta_est` from outside the observer.
- **Observer**: `SMO_Update` (eSMO + PLL; the legacy SMO was removed 2026-10-27) fills `smo.theta_est`, `smo.omega_est` (electrical rad/s), `smo.emf_magnitude`, and returns a lock flag. Parameter-dependent coefficients are precomputed in `SMO_Compute_Coefficients()`; call `SMO_BLDC_Specs_Update()` after changing Rs/Ld/Lq.
- **Low speed (HFI)**: with `foc->hfi_enable`, `MOTOR_RUNNING` runs `FOC_Current_Loop_HFI`: an HF-injection tracker (`hfi_theta`, `hfi_omega`) takes over below `HFI_OMEGA_LOW` (hard-coded 400 rpm, not yet measured) and hands back to the eSMO above `HFI_OMEGA_UP` once they agree; `foc->theta`/`foc->omega` are the active estimator's (the speed loop uses `foc->omega`). Startup is still Align -> I-f -> eSMO. Never seed or write the eSMO's state from the HFI side. See the HFI block in `foc_lib.h`.
- **FreeRTOS tasks**: `StartDefaultTask` (init, offset measurement, one-shot calibration + test run, then idles) and `StartSpeedControlLoop` (200 ms speed PI writing `iq_ref`; must only act in `MOTOR_RUNNING`).
- Current-sense zero offsets are measured at startup in `StartDefaultTask` (motor must be stopped).
- `FOC_t foc` is a single global shared between tasks and the ISR without locking — treat concurrent access as intentional and be careful adding writers.
- Fast math in `foc_lib.c`: table-based `Fast_Sin/Cos/Sin_Cos` (must call `Init_Trigonometric_Tables()` first; `FOC_Init` does), FMA-based `Normalize_Angle`, polynomial `Fast_Atan2`, `VSQRT` `Fast_Sqrt`. The `TRIG_NOINLINE` slow paths are deliberate (keep the fast paths frameless) — do not inline or merge them.

## Memory constraint

RAM was **~89 % (58 KB / 64 KB)** before the 2026-10 rework; the trig table shrank from 8 KB to 5 KB since then, but re-check with `pio run`. FreeRTOS heap is 32 KB (`Inc/FreeRTOSConfig.h`, `heap_4`). `FOC_t` carries the calibration buffers (`INJECTION_ROUNDS` = 256 × six float arrays, 6 KB; the write-only PWM/ADC copies were removed 2026-10-30, RAM now ~78.5 %). Adding task stacks or buffers can overflow at link/runtime — check the `pio run` RAM line after any such change.

## Conventions

- `Lib/` holds the reusable `foc-lib` (PlatformIO auto-discovers it). `shared/` is referenced in `platformio.ini` (`build_src_filter`, `-I shared`) but does not exist; harmless today, relevant if you add shared code.
- Tunables (motor params, gains, ADC scaling, rated values) are `#define`s in `Lib/foc-lib/foc_lib.h`. Startup tunables and the board/sensing/motor constants (`PWM_RES`, `ADC_RES`, `ADC_V_REF`, `R_SHUNT`, `V_OFFSET`, `V_GAIN`, `V_BUS_GAIN`, `CURRENT_SENSE_POLARITY`, `RS`, `LS`, `POLE_PAIRS`, `FLUX_LINKAGE`, `V_RATED`, `I_RATED`, `I_PEAK`, `V_BUS_MIN`, `V_BUS_MAX`) are `#ifndef`-guarded defaults for the reference setup. A port overrides them in its `foc_lib_conf.h` or with `-D` (e.g. `-DOMEGA_FORCE=500.0f`); derived constants (`TS`, `ADC_2_*`, `V_2_CURRENT`, `ADC_OFFSET`) follow automatically. Controller gains and calibration settings are not guarded.
- Units: angles in electrical radians, speeds in electrical rad/s unless a name says otherwise.
- `.vscode/c_cpp_properties.json` and `.vscode/launch.json` are auto-generated — do not hand-edit; change `platformio.ini` instead.
- `tools/sim/` holds host-side simulations of the library (not built by PlatformIO).
